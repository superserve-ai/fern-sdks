## Project Overview

Superserve SDK repository — auto-generated TypeScript and Python client SDKs for the Superserve API. Superserve provides sandbox infrastructure (Firecracker MicroVMs) to run AI agents in the cloud.

## Architecture

- `openapi.yaml` — Single source of truth. The OpenAPI 3.1 spec defines the entire Superserve API (sandboxes, exec, files, system health).
- `fern/` — Fern code generation config. `generators.yml` defines which SDK generators to run and where output goes. `fern.config.json` holds the org/version.
- `sdks/typescript/` — Generated TypeScript SDK (fern-typescript-sdk v3.63.0). Exports `SuperserveApiClient`, namespace `SuperserveApi`.
- `sdks/python/` — Generated Python SDK (fern-python-sdk v5.3.2). Package `superserve`, classes `SuperserveApi` / `AsyncSuperserveApi`.
- `examples/` — Working usage examples for both SDKs.

**The SDK code under `sdks/` is auto-generated by Fern. Do not hand-edit these files.** All changes should flow through `openapi.yaml` → Fern generation.

## Commands

### Generate SDKs

```bash
# Generate TypeScript SDK (default group)
cd fern && fern generate --group local

# Generate Python SDK
cd fern && fern generate --group python-sdk
```

### Run examples

```bash
# TypeScript
cd examples/typescript && bun install && SUPERSERVE_API_KEY=<key> bun run start

# Python
cd examples/python && python3 -m venv .venv && .venv/bin/pip install httpx pydantic
SUPERSERVE_API_KEY=<key> .venv/bin/python example.py
```

## API Structure

The API has four resource groups:
- **Sandboxes** — CRUD + pause/resume lifecycle for MicroVM sandboxes
- **Exec** — Execute commands inside sandboxes (sync + SSE streaming)
- **Files** — Upload/download files to/from sandboxes
- **System** — Health check

Auth is via `x-api-key` header. Environments: production (`api.superserve.ai`), staging (`api-staging.superserve.ai`), local (`localhost:8080`).
